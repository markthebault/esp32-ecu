# Flex input architecture draft

`FLEX-G38-DRAFT1` reserves GPIO38 for a protected flex-input candidate on a new carrier revision. The [machine-readable contract](architecture.json) records allocation, capture ownership, shared I2C limits and unfinished gates. The [original frontend](frontend.json) remains preserved; the [compact frontend](frontend-compact.json) and [ordinary RGB driver](status-led.json) accompany the [routed A6 development checkpoint](../../docs/engine-a6-layout.md). Native checks and independent review accept that development draft with explicit holds. No fabrication or sensor-connection release is supplied.

The preferred allocation moves the external GPIO38 WS2812 status function to an ordinary RGB LED driven through a direct-solder PDIP18 MCP23008 at address0x21. Existing switch acquisition remains at0x20 with its GP7-to-GP6 challenge and full-byte IODIR guard. IO7 must be configured as output even when it is NC on the new expander. [Microchip DS20001919I, Register1-1](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP23008-and-MCP23008-Data-Sheet-DS20001919.pdf)

GPIO45/46 stay unconnected. GPIO46 must be low with BOOT low for joint download; GPIO45 can select VDD_SPI without a verified eFuse override. Chip Reset strap sampling differs from resets that retain GPIO state. This allocation avoids depending on an unmeasured strap gate, reset retention or the supplier module's fuses. No eFuse change is requested. [Espressif boot documentation](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/boot-mode-selection.html)

Historical compact GPIO38 LED firmware and generic GPIO38 ARM firmware cannot own the new input. The separate `compact_n16r8_flex_dev` build excludes every old RMT initialization/write and explicitly disables GPIO output before configuring GPIO38 as an input. Historical/default builds keep their WS2812 wiring. The development build now connects MCPWM capture to the serialized control owner and exposes capture diagnostics. Required data remains inhibited until a coherent, confirmed, current target sample exists; physical engine outputs stay OFF. No device has been flashed.

The existing group0 capture timer stays running and calibrated. Its third channel acquires both flex edges at priority3; crank/cam keep their channels, status and timing. The hardware has one event latch per channel. Software queues cannot establish lossless capture. The [portable ingress](../../firmware/include/ecu/flex_ingress.hpp) implements bounded handoff and suppression decisions only. The target now supplies source-specific channel2 interrupt masking/clearing, one shared lock, a single floating-point owner in `engine_service::observe`, actual calibration/revision binding and completed-control ACK routing. SDK group0 channel allocation and interrupt-enable ownership are private to this timing service; crank/cam SDK enable/disable does not run concurrently with the runtime LL mask. Every stop/rearm or binding change must also invalidate the separate floating-point Capture series. Ingress queue clearing cannot do that itself. Only the owning worker may forward both fault tickets after a completed matching invalid control evaluation; the ingress cannot verify control execution.

Sample callback/owner time after taking the same lock used for the ingress call. A timestamp sampled before waiting can be older than an intervening event and correctly fail the monotonic-clock check, even when an ACK's metadata is stale. Snapshot holdoff status is evaluated at its recorded `last_observed_us`, not at the time a diagnostic reader receives it.

The32-callback/10ms fixed window applies to matching active callbacks within an armed episode. It is not a global IRQ budget across inactive/foreign callbacks or arbitrary stop/arm cycles. The trusted owner must honor local interrupt suppression and the ACK/holdoff retry path, and must not implement noise retries as repeated normal stop/arm.

Pop followed by floating-point work outside the lock is not a publication fence. Retain context, fault generation and arm boundary with the pop. Before publishing, atomically revalidate current context/generation/armed state and the event timestamp against the current arm boundary, then commit under that same lock or an equivalent versioned commit. A mismatch discards the result and invalidates/reacquires the separate Capture series. The edge has no generation field, so the companion snapshot/version must be retained. This owning-worker fence is implemented in `flex_capture_owner.hpp` and the target backend. A configuration change, ingress fault or arm boundary mismatch rejects publication and restarts the separate waveform series. Intentional rearm clears gap continuity while retaining monotonic time, source and fault history.

Each accepted command retains the original sample deadline and Capture fault generation. Newer samples cannot extend that deadline. A failed or invalid publication cancels prior queued demands, including a Capture-domain fault that did not fault the integer ingress. The GPTimer and worker check the ticket before execution. Both fuel and spark must be cut to bypass the flex guard. Flex callbacks never refresh crank/cam tooth age.

Flex timestamps use the earlier startup sync-bracket endpoint as a fixed conservative epoch. Raw pulse differences retain sub-us integer quantization instead of the crank mapper's per-callback uncertainty clamp. The common timer and crank/cam conversion remain unchanged. This static architecture does not measure physical pulse skew or interrupt loss.

The new software implements one bus owner and one shared3ms transaction deadline per5ms tick. Required switch guards run first. LED work uses remaining slack, coalesces requests and advances one bounded operation at a time. Two-transaction LED verification waits for at least two remaining integer-ms timeout slots; it never starts a second3ms budget. Bus release preserves either device's ownership. SDK allocation/deletion lack timeout APIs; CPU/lock overhead and target timing remain unmeasured, so this is not a hard WCET claim.

GP0/1/2 are active-high red/green/blue driver inputs. All GP pins are outputs (`IODIR=0`); unused GP3..7 are NC and held low. The driver writes OLAT off before direction, uses IOCON.ODR=1 (`IOCON=4`) and verifies the full sequential register image plus an independent trailing IODIR. The nonzero IOCON marker rejects byte-mode reads that would otherwise repeat zero across an all-zero frame. This software contract does not select a transistor/LED circuit or authorize direct sensor/LED connection.

Normal requests steady green; pairing and detected problems request blue/red with250ms on/off intervals, with fault priority. MCP outputs can retain green after CPU/bus failure. The paired-screens UI shows requested policy separately from verified latch, age and fault state, and clears readback on a failed HTTP poll. Known historical green is never presented as a current optical or CPU-health measurement. A missing LED alone does not add an engine-control dependency; a failed shared bus still invalidates required switch inputs.

The frontend concept uses a direct-solder classic TI LM2903P PDIP8, an attenuated input with filtering/clamping before its immediate feedback node, and an open-collector output through a4.7k/47k GPIO divider. Three750R pullup resistors share dissipation. The spare U7 Schmitt gates remain unchanged: omitting them avoids relying on interpolated3.3V switching thresholds. This is a conditional circuit design, not a protection rating. Preserve the physical sensor LOW width. The core's2µs endpoint allowance covers timestamp quantization, not an unmeasured circuit delay.

The candidate electrical profile follows AEM35-2200's9..18V supply and50..150Hz/1..5ms convention. Its manual's page3 pullup prose swaps pins1/3 relative to the page4 table. Neither that contradiction nor a generic GM connector is an accepted harness drawing. Exact sensor markings, current, leakage, LOW voltage and physical connector mapping remain unresolved. F3 is only a candidate overcurrent element: inherited VIN_PROT is not an18V limiter and may exceed the sensor operating range. Bench connector voltage is an explicit regulated boundary in the simulations.

`tools/run_flex_circuit.py` executes ngspice equivalents and replays resulting GPIO crossings through the actual portable Capture, keeping synthetic source labels and default8-cycle qualification. The current62-case matrix covers nine conditional crossing thresholds, ten integer clock phases, joined supply/offset/bias/leakage/TCR and5% filter-cap corners, step refinement, slow/noisy drive, partial power, an assumed cold-clamp bound and power-off rail bleed. The500pF RAW shunt is an assumed combined sensor/cable/connector/PCB load, not a manufacturer cable specification. The explicitly modelled conditioning network adds its own capacitances.

The tests retain intentional failure witnesses. Extra asymmetric comparator delay or5nF loading can push endpoint pulses outside Capture's bounds; the firmware tolerance is unchanged. A distorted midrange signal may still qualify. The slow-ramp test's pulse parameter is a control plateau, not a physical AEM pulse-width measurement. Thus passing Capture is not evidence of signal accuracy. Classic comparator delay is typical-only, its stated LOW test uses different overdrive, and the ESP32 input-level table has stated3.3V/25°C conditions; target margins over temperature need confirmation and measurement.

An open inherited R7 rail bleeder lets the equivalent unpowered3V3 rail rise to about0.42V under the synthetic+36V signal experiment. With R7 present it stays near0.9mV in that model. Neither result proves arbitrary power-sequence safety. The−36V signal/+18V sensor experiment dissipates about0.42W in each pullup resistor without tripping the100mA PTC; duration, derating and assembled heat remain holds. These are conditional experiments, not automotive fault or surge ratings.

The RGB concept adds MCP23008 at0x21, a reset-supervisor candidate and three leaded NPN stages for a common-anode ordinary LED. The candidate LED is Kingbright WP154A4SEJ3VBDZGW/CA, with a unique PH5 carrier connector and four populated contacts. GPIO high selects red/green/blue. Native CAD, current/headroom/reset/bus/power checks and a sealed optical-window assembly remain separate work. An expander latch can retain green after CPU or bus failure; its readback is still advisory.

Independent circuit review found that the initial MCP121-300 supervisor could remain reset at the low end of the declared normal rail. The revised candidate is MCP121-270E/TO. Its25°C maximum trip plus hysteresis is2.828V; the hysteresis limit is specified at25°C, so this is not an all-temperature release guarantee. Loaded reset, rail ramps and deep brownout still need measurement. The lower trip is not a3.0V brownout monitor. [Microchip DS20001906E, pages4–5](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP102-Data-Sheet-DS20001906.pdf)

The3.3V MCP23008 path uses the low-voltage−40..85°C table region. E/P ordering does not establish3.3V operation at125°C. Its tabulated output-high test points also do not guarantee loaded GPIO-high readback with the present2.2k NPN base drive over the whole rail/temperature range. Register/latch verification must not be described as measured brightness or guaranteed loaded-pin voltage. [Microchip DS20001919I, Table2-1](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP23008-and-MCP23008-Data-Sheet-DS20001919.pdf)

The first fitting262-footprint placement had long comparator summing/reference connections and was rejected as an electrical placement. Its router was deliberately stopped and the input/logs retained. The revised same-envelope placement brings the critical passives closer to U18; this does not bind the model's assumed parasitics to a real PCB. Short feedback loops, local bypass ground returns, copper extraction/review and physical timing remain separate gates. Earlier carrier copper and assembly coordinates cannot be used for this repacked A6 draft.

Use fresh output paths to reproduce the conditional input checks:

```sh
uv run --offline --with numpy python -B tools/test_flex_frontend.py
uv run --offline --with numpy python -B tools/run_flex_circuit.py --frontend hardware/flex-input/frontend-compact.json --ngspice PATH_TO_NGSPICE45_2 --output .cache/engine/NEW_FLEX_CIRCUIT
```

No circuit manufacturer model, physical sensor, actual GPIO/RTOS or engine is executed by these commands. Source snapshots, raw voltage captures, independent DC/capture probes and explicit rejection witnesses must stay attached to any claimed result. Native circuit/CAD and complete-board review remain distinct from this conditional model review. Omitting `--frontend` selects the preserved original profile. The compact matrix includes C164 at its nominal ideal value; effective X7R values, ESR/ESL and supply transients remain unqualified.

The120×120mm limit, ordinary leaded parts, direct-solder DIP, pluggable N16R8, inward10mm antenna allowance and sealed PAIR/RESET remain constraints. Physical dimensions and RF/fit behavior remain unverified. A3/A4/A5 sources and manufacturing records remain historical copies. Physical engine outputs remain inhibited.

Build only into a new owned directory, for example:

```sh
python3 -B scripts/build_firmware_preserved.py --output .cache/engine/NEW_BUILD --environment compact_n16r8_flex_dev
```

PlatformIO automatically removes its build cache after project configuration changes. The first direct build for this increment cleared previous generated environment caches before retention was applied; their original ELF bytes were not recovered. Source/history and frozen reports remain. The wrapper now retains the current default cache, sets a fresh `PLATFORMIO_BUILD_DIR`, verifies source/cache hashes and archives each resulting ELF losslessly. It never flashes.
