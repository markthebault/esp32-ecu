# Independent transient-fuel architecture assessment

Baseline: project `64c21ed`, schema5/own006, and unchanged Speeduino `9ff5aae44de51fdc00d3fb1c7c2bfc1f0d0b3e20`. This is design/reference assessment before acceptance of a new implementation. No production files, services, hardware or external checkout were modified by this reviewer. Cache-only probes execute production sensor/correction functions or the committed legacy project controller. Neither probe validates an engine.

The proposed increment is coherent: explicit **legacy_tps**, **off**, **tps_rate**, **map_rate** modes; multiplier/adder selection; bounded rate tables, finite event duration and gates; positive-AE RPM/cold tapers; separately defined multiplicative deceleration; and complete configuration/observability support. Existing protected calibrated MAP/TPS channels are sufficient. No new PCB input is required for the algorithm. Electrical sensor/engine/vehicle qualification remains separate.

## Preserve schema5 behavior exactly

The current legacy algorithm (`engine.hpp:144,174`) differentiates TPS using control-step time, decays the previous extra multiplier exponentially, takes the larger of that residual and the new positive-rate contribution, and clamps the instantaneous extra contribution to50%. Negative TPS movement does not request decel fuel reduction. Cranking/fault/stopped states reset legacy AE; current EGO eligibility uses ae_<1.02. Sensor values are stored into previous_tps_ before validation. These details affect recovery and cadence.

Keep this old calculation and its three existing settings as an explicit branch. Mode legacy_tps must remain the default for all schema<=5 JSON/MSQ imports and the new illustrative default. Off means an intentional new neutral behavior, not a migration default. Do not repair old differentiation/recovery semantics while claiming exact compatibility. Preserve historical definitions and all existing base offsets; add the new object through an explicit schema6 migration, page extension at4992, and own007 identity. Freeze field ordering independently of mutable defaults iteration.

`legacy_golden.cpp` builds against an immutable `git archive64c21ed` header tree. Its fixture covers step/decay, threshold/cap, negative movement, repeated acquisition stamps, stale recovery, crank-to-run and EGO gating. For example TPS0→1 over5ms gives AE1.4000000189989805; after a further5ms constant TPS it is1.3950311390341041. The old branch produces that same first AE even when both values have sampled_us0. This is a documented legacy property, not recommended timing for the new mode. Same compiler/library golden output can catch unintended changes; cross-target floating-point checks require an explicit tolerance.

## New acquisition/history contract

The target scans eight MCP3208 channels every5ms (`app.cpp:177,263`), captures the scan-start clock, then passes that sampled_us through engine_service. Engine binding converts calibrated raw values directly; it does **not** apply the sensor UI's filter_ms. MAP/TPS are first/second sequential scan channels, so the common timestamp also has scan/transfer uncertainty that has not been measured physically.

- New-mode differentiation uses increasing **sampled_us**, not task now or a nominal loop frequency. Validate new sensor samples before updating history. The first eligible running sample seeds history and cannot trigger enrichment. Calibration/tune changes, stop, cranking, required sync/phase loss, stale input, acquisition-clock reversal or a gap beyond the declared limit discard the event and rate baseline. Root's existing control reset/configuration fences should reset this module too.
- Repeated acquisition stamps never generate another derivative or retrigger. They may retain a still-valid event until its original deadline; ordinary stale-input supervision still cuts when the source is too old. A source timestamp earlier than the baseline is invalid, not an enormous unsigned interval.
- The explicit sample_period_ms is a minimum differentiation window. Once elapsed acquisition time reaches it, use the actual elapsed interval and calibrated endpoint difference, then advance the baseline regardless of whether min-change passes. That defines a predictable slow-motion/noise gate. If an accumulation-from-last-motion policy is desired instead, make it an explicit different contract; do not accidentally mix the two.
- A source window of at least5ms matches the current physical acquisition cadence. Native1ms runs may call the controller faster but should not create a different physical rate window. If a configurable low-pass is not included, describe endpoint-window differentiation plus min-change gating honestly; the existing UI filter setting is not an engine filter.
- Require both |delta|>source_min_change and |rate|>source_threshold to accept a trigger, matching the pinned strict inequalities where desired. Use physical % andkPa, not raw ADC counts. A lookup above the final rate bin clamps to the final curve value. Expose out-of-table/clamped state rather than implying a measured rate equals that endpoint.

## Event, taper and deceleration policy

The event is a finite state machine, not an unbounded integrator. Positive accepted rate looks up an **extra fuel percent** from the selected table; negative accepted rate selects a configured **total fuel percent**. One selected source operates at a time. TPS/MAP blending is outside this first contract and should not be implied by retaining both editable tables.

- Seed the event time from the accepted acquisition timestamp. Compare expiry on **every control step**, not only new rate evaluations. If processing begins after the whole event lifetime, do not inject a late full-duration event. Zero duration should explicitly mean no event. Use subtraction or checked addition so near-UINT64_MAX timestamps cannot wrap a deadline.
- An increasing same-sign |rate| retriggers; an equal or weaker same-sign rate retains the original expiry and held demand. A newly accepted opposite sign cancels/replaces the old phase immediately. This is a sensible documented difference from pinned Speeduino, which can hold positive enrichment through a weaker negative transient. Trigger/retrigger counters should saturate or have documented wrap semantics.
- Explicitly choose whether RPM/CLT tapers are latched at event start/retrigger or recomputed during the hold. Pinned Speeduino latches them when computing a new AE amount. Latching gives the clearest first comparison. The output still obeys later hard cuts and capacity limits.
- Apply RPM and cold modification to **positive extra percent**, then cap it at the configured global extra-fuel authority. Neutral baseline remains100%. An RPM taper should decrease extra toward0 between strictly ordered start/end values; cold modulation should approach1/100% at its warm endpoint. Validate finite coherent endpoints even when the selected mode is inactive. Preserve a distinct clamped-authority flag.
- Decel is a total multiplicative fuel amount:100% neutral,70% means0.70 times ordinary fuel,0% requests no injector opening. It is not an extra−30% table value and is not DFCO. Define whether >100% decel is supported; Speeduino permits it, but a first reduction-only contract may deliberately use0..100. Do not apply positive-AE RPM/cold tapers to decel unless explicitly adding and documenting that difference.
- Cranking, stop, faults and active DFCO take precedence over a transient event. Clear/reseed new-mode history at those transitions so a prior throttle event is not resumed later. New decel0 sets fuel_cut and pulse0 for all injector channels; do not leave a deadtime-only pulse. Spark, pump/fan and fault behavior remain separately defined. Final rev/sync/capacity cuts must dominate both application modes.
- Gate lambda feedback on new event state, including additive AE where the scalar multiplier can remain1. A neutral-valued event may still be diagnostically active; define whether it gates feedback. Preserve the exact old gating in legacy_tps.

## Multiplier and adder semantics

Multiplier AE scales the ordinary effective fuel mass, before injector deadtime. Root's proposed adder reference is appropriate for a Speeduino-style first comparison: full four-stroke **per-cylinder** fuel mass at100kPa,25C,100%VE andlambda1, using the configured cylinder volume and stoichiometric AFR. That reference is independent of current MAP/VE/WUE/EGO and target-lambda changes. Its percent is not a percent of the current pulse width.

For additive positive AE, compute ordinary fuel plus extra reference mass, then apply any physical-cylinder fuel trim to the sum; divide by actual openings per cycle and flow; add deadtime once per opening. Check final channel pulse/duty demand. This preserves sequential versus batch/semi accounting and prevents deadtime or enrichment being counted twice. Decel remains multiplicative even when the positive application mode is adder.

The pinned production order is visible in `fuel_calcs.cpp:128-156`: AE adder adds a percent of **calculateRequiredFuel**, after ordinary fuel corrections/open time; calculateRequiredFuel halves the full-cycle reference for nonsequential four-stroke operation. Adding effective mass before deadtime is equivalent under these assumptions; cylinder-trim order must be checked against actual pinned channel code in the full comparison. The project's current mass model and Speeduino's reqFuel0.1ms byte are not exactly equal: the existing2L/300cc/min benchmark deliberately rounds the reference to10.7ms. Record that quantization; do not demand zero pulse-width difference or silently clamp unsupported reference parameters. Speeduino's reference byte cannot represent every engine/injector combination accepted by the project.

Validate all thirteen proposed scalars, two enums and four four-point arrays, including inactive branches. Require strictly increasing finite rate axes and finite bounded values. Define limits for duration, sample window, min-change, thresholds, maximum extra, decel total, RPM and cold tapers in physical units. A sample window/gap policy must not permit division by zero. Existing15ms injection, duty and flow limits remain authoritative after composition.

## Pinned Speeduino reference contract

Use actual production setup/storage, readPolledSensors, correctionsFuel, fuel calculation and scheduling; the adapter supplies explicit configuration and observations only. For a controlled first profile, use:

- configPage2.aeMode TPS0 or MAP1; aeApplyMode multiplier0 or adder1. Unsupported blend modes must be rejected rather than coerced.
- taeThresh/maeThresh are direct byte %/s orkPa/s thresholds. taeMinChange is raw0.5% units; maeMinChange raw1kPa. Both min-change and rate trigger/reset tests are strict>.
- aeTime is a10ms raw byte. The misleading TIME_TENTH_MILLIS name does not mean0.1ms: its scale is10000us.
- configPage4.taeBins/maeBins[4] are stored in rate/10; taeValues/maeRates[4] are **extra** percent0..255. Targets representable in the project may require reference quantization or rejection. Log intended and actual arrays.
- aeTaperMin/Max are RPM/100; cold temperatures are C+40; aeColdPct100..255 is a multiplier on positive extra. decelAmount is total fuel percent and bypasses these positive tapers.
- TPS is sampled by the33ms timer (~30.303Hz) but computeTPSDOT uses constant TPS_READ_FREQUENCY30. The sensor path maps10-bit ADC→8-bit ADC/filter→0..200 half-percent TPS. TPSdot is quantized from that0.5% delta, multiplied by30 and clamped±2550.
- MAP polling is1kHz, but accepted MAP readings depend on mapSample instantaneous/cycle average/cycle minimum/ignition-event average and filtering. Current MAP is integerkPa. MAPdot uses the accepted reading delta/time, with integer reciprocal division and clamp±2550. Log accepted delta/time, not merely ADC supply cadence.
- Active same-sign or opposite-sign samples restart the held phase only if the new absolute rate exceeds the old activation peak. A weaker opposite sign can leave the previous phase active. Expiry is tested only at that source's update cadence. An expired phase clears dot for that evaluation, so immediate re-entry has additional discrete effects.
- Reference readback must include mode/application, thresholds, min-change, duration, table axes/values, taper fields, filter coefficients, mapSample and actual reqFuel. Observe TPS/TPSlast, TPSdot, MAP, accepted MAP delta/dt, MAPdot, AEamount, accel/decel flags, AEStartTime, final corrections, per-channel pulse widths and actual injector edges. Keep commanded sensor values separate from quantized production readings. The existing sensors IPC does not itself advance a production loop; status immediately afterwards may still describe the prior evaluation.

## Oracles and simulator acceptance

Use separate levels of evidence:

1. Mathematical unit fixtures cover two-point known rates, physical-unit lookup/interpolation/clamping, exact gate boundaries, duration/expiry between samples, equal/stronger retriggers, both sign reversals, taper endpoints, acquisition duplicates/reversal/gaps, first sample, stop/crank/fault/DFCO/configuration reset, nonfinite inputs/config and timestamp overflow. Identical acquisition traces delivered at different control cadences should produce the same accepted events and time-integrated held demand, within declared output sampling. Test max extra and decel0 explicitly.
2. Algebraic pulse fixtures check multiplier versus reference adder across MAP/VE/CLT/EGO changes, plus batch/semi/sequential openings, deadtime, trim interaction, final capacity and zero-flow cut. With extra0, the new calculation is neutral. With application multiplier, reference adder is unused. With decel0, no virtual injector edge is scheduled. Run the committed legacy golden fixture unchanged for mode legacy_tps and every old import.
3. Production reference replay uses declared sensor quantization/filter/mapSample and fixed calibration, including steps, slow ramps, noisy/subthreshold staircases, short reversal, repeat bursts, unequal sensor/control cadence and actual native16/native32 limitations. Expect and explain bounded algorithm differences instead of tuning the oracle until it agrees. Native16 counter tests do not establish AVR int/long promotions, CPU cost or real acquisition timing.
4. Full research-plant runs couple actual injector/spark edges to the existing independent wall-film/port/charge model and Modelica air path. Compare AE off, legacy, new multiplier and adder at identical physical parameters for warm/cold throttle ramps, quick lift/reopen, load changes and repeated blips. Log delivered fuel, wall/port inventory, trapped air/fuel, actual cylinder lambda, delayed valid sensor lambda, torque/RPM response, saturation, cuts and conservation residuals. Hold plant geometry, wall-film law and fuel/rotor/combustion parameters fixed across ECUs. Sweep predeclared film fraction/time constants and sensor delays, and halve integration step. The stock film model is empirical; lower model lambda error does not establish a correct engine tune or superiority on a real engine.

Negative controls should disconnect compensation from fuel, use AE0, force a neutral table, disable wall film or vary its parameters independently, freeze/repeat a sensor timestamp, and inject invalid/stale MAP/TPS. A compensation method should affect delivered fuel through actual pulses before it is credited with lambda/RPM improvement. Feedforward AE must not change the plant's wall-film physics or invent a direct torque correction.

## Memory, wire and observation budget

Committed native sizes: Tune4720B, RuntimeSample312B, Row328B, Recorder84056B, Session9792B. Current page4992 and live256 are already allocated contracts; only52 tune bytes at the page end are reserved, and the live block has no space remaining.

Root's proposed124-byte config plus4 reserved bytes at4992→5120 is compact and complete. A new40-byte observation raises the256-row recorder by approximately10KiB. An explicit96KiB recorder budget appears plausible, subject to actual sizeof and final ELF/heap review, not just increasing assertions. Session will cross its old<10000-byte test ceiling (approximately10048B after config/page growth); task-side heap ownership should remain explicit.

The live block cannot silently grow past256 while Session r count stays capped256 and the INI assumes one read. Either define and test segmented live reads with the new identity, update every target/native/backend/INI bridge and actual application acceptance, or expose additional diagnostics on an explicit separate surface. A compile/test-only codec cannot establish vendor application compatibility. Preserve historical layouts and do not repurpose old validity/source fields.

New observations should expose selected source/mode/application, qualified rate/delta/dt, event state/reason and age/remaining lifetime, trigger peak, table extra, RPM/cold factors, applied extra/total factor, reference adder mass/ms, clamp/cut flags and exact counters. Keep unavailable distinct from zero, source/freshness explicit, and uint64 identities/counters exact strings through browser/MSL. Update shared C++ snapshot, JSON, MSL, browser collector/export, Python/native fixtures and INI together. Test allocations across the enlarged complete16-row page, formatter capacity, whole-page CAS/persistence, legacy imports and all reserved/extension boundaries.

The assessment supports implementing this bounded increment. It does not approve a not-yet-reviewed implementation, calibrated transient compensation, physical injector/driver operation, online TunerStudio acceptance or a complete engine ECU.
