# Independent secondary-table architecture assessment

Project baseline: `e2b7c832b92384caae6cf379092ac6944129e237`. Reference: unchanged Speeduino `9ff5aae44de51fdc00d3fb1c7c2bfc1f0d0b3e20`. This review audits the intended next feature, not acceptance of an implementation that does not yet exist. No project or upstream source was edited. Files here are cache-only review evidence.

## Exact reference contract

1. Fuel and spark modes are independently Off, multiply, add, conditional switch or input switch. There is no continuous percentage interpolation between the two maps in this pinned implementation. Historical/unmerged flex-blend proposals do not establish a supported feature here.
2. Each secondary table independently selects MAP, TPS or100×IMAP/EMAP. Its coordinate is distinct from the primary table. The secondary fuel lookup does not change the primary `fuelLoad`; the AFR target remains on the primary fuel coordinate. Cylinder trim policy similarly must not silently follow whichever fuel table happened to win.
3. Fuel multiply is rounded integer primary×secondary/100 and saturated to255. Add is primary+secondary saturated to255. Switched mode replaces primary. Off/untriggered/unknown mode leaves the already initialized primary result intact, clears the active bit and reports secondary VE0. The caller must initialize `VE=VE1` every loop.
4. Conditional switching uses **strict greater-than**, with no hysteresis or debouncing: RPM, absolute MAP kPa, raw TPS or ethanol percent. TPS status is physical percent×2; conditional INI scale is0.5%. TPS table coordinate is physical percent×4 before native table load/2 storage. A physical50% threshold is raw100; it is inactive exactly at raw100 and active at101. Do not apply the table coordinate multiplier to condition thresholds.
5. Input switching reads the configured virtual/physical digital pin and compares it directly with configured polarity. No qualification, freshness, debounce or wire-break detection is supplied by secondaryTables.cpp. Initialization chooses pin/pullup elsewhere. Project input health can be stronger, but differences must be explicit.
6. Primary ignition corrections run **before** multiply/add. Switched spark looks up table2 then runs the complete correction chain on that value. Thus primary20deg with10deg soft retard, plus secondary150%, gives15deg; additive20deg gives30deg; switched20deg gives10deg. Applying a final project protective retard after composition is a reasonable different policy but is not the same calculation and needs explicit diagnostics/reference comparison.
7. Every secondary spark mode is bypassed while cranking or fixed timing is enabled. The mode is inactive and advance2 is0. The native main loop classifies rotation after these calls, so a full-loop start/stop transition may carry a prior-loop state for one iteration. Direct function tests do not establish startup loop timing.
8. Reference spark multiply interprets table2 as0..255 percent, clamps negative values to0, combines with corrected advance1 and clamps the result to signed8-bit range. Add clamps table2 to signed8-bit then adds/clamps. The INI exposes0..215% for multiply and-40..70deg otherwise; physical raw cells are U8 with-40 translation. In multiply mode the logged `advance2` is percent minus127, not degrees. A project should log the actual percent and its unit instead of reproducing this diagnostic encoding.
9. Current project table/angle limits remain narrower than Speeduino. Do not silently expand actuator angle limits as a side effect of adding arithmetic. Expose composition/clamp state, including whether cylinder offsets and soft retard occurred before or after composition.

## Recommended end-state software contract

- Two full16×16 maps with their own RPM axes, physical load axes, source and axis-basis metadata. Preserve values on source changes; keep the explicit calibration acknowledgement used by the primary tables. A source selector must not silently convert table units or reinterpret spark percentages as degrees.
- Independent per-table mode, condition selector, physical threshold and input channel/polarity. All config must be validated even if a table is Off; inactive table data is retained for editing. Legacy schema1..7/own001..008 migrate to Off without changing previous maps, bytes or revisions until an explicit save.
- Keep a single source-of-truth dependency calculation shared by native core and target binding. Any MAP condition requires MAP even if both table sources are TPS. A secondary pressure-ratio coordinate requires valid absolute EMAP and must participate in the J16 EMAP/baro role conflict. Choose and document either static configured dependencies or active-only table dependencies; for the latter, test the exact activation sample so missing data cannot quietly select primary or extrapolate.
- Preserve primary fuel coordinate for lambda `follow_fuel` and trims unless a separate explicit policy is added. Combined VE changes modeled charge/fuel before existing AE/EGO/cylinder trim/deadtime/capacity operations. Zero combined fuel must retain the existing no-deadtime-only-opening behavior and reference-adder distinction.
- A selected unavailable/stale/future input is unknown and faults the configured consumer. Do not turn an invalid switch read into inactive/primary fallback. Off and bypassed paths need explicit evaluated/available state so a consumer can distinguish not required from a real inactive sample.
- No qualified ethanol source currently exists. An ETH% condition needs a real source/age/qualification contract; zero-filled ethanol is not one. A core can accept explicitly qualified synthetic ethanol for simulation while the target/UI reject or visibly fault an unavailable physical source. Full physical flex support remains a separate open feature.
- Proposed switch acquisition policy: per-input raw state plus valid/source/sample timestamp; independent50ms maximum freshness checked by the control consumer; future/reversed stamps invalidate; bounded polling5ms; stable20ms debounce before the initial state is valid. A normal transition may retain the last valid debounced state for20ms, then publish the newly stable state. A bus/NACK/config failure immediately invalidates. Startup, config changes, timestamp reversal or acquisition discontinuity must reset the debounce epoch. Require a fresh stable20ms interval again rather than inheriting an old state across a long gap. These values are a recommended explicit project policy, not Speeduino behavior. Distinguish last successful read age from last debounced transition age so a held switch does not falsely become stale.
- Reject an input channel/pin role conflict. If fuel and spark deliberately share one input, apply the same coherent sampled input state to both in a control observation; do not let two independent reads split their selection accidentally.
- Runtime diagnostics should include primary value, secondary value and unit, secondary coordinate/source, mode/condition, condition value/threshold/known state, raw/debounced switch state and age, selected/active/evaluated state, composed result, final protected result/clamp flags and explicit invalid reasons. Defaults/Off must preserve previous arithmetic and edge traces exactly.

## Existing hardware and the J4 accessory route

The authoritative A4 and A5 net contracts show no spare already protected general switch inputs. Current carrier J18/GPIO9 is the protected CAM path. It could only be an explicitly exclusive role in a crank-only strategy; it cannot supply full sequential cam plus two independent switches. J16 is the protected POSTCAT/EMAP/baro ADC path and should retain its pressure role. PAIR/GPIO0 and EN RESET are enclosure service controls; neither is a replacement for an engine table-switch input. GPIO19/20 are USB, GPIO35..37 are reserved by the selected octal memory module, GPIO45/46 are strapping concerns, GPIO38 is separate status LED, GPIO3 is the A5 idle command, and ARM/INTERLOCK/watchdog remain assigned.

**J4 is a viable internal expansion route, not an existing protected switch port.** Pin order is1GND,2+3V3,3I2C_SDA/GPIO41,4I2C_SCL/GPIO42,5SAFE_N. Existing R16/R17 are4.7kohm pullups to3.3V. No current firmware I2C expansion driver was found. J4 has no spare reset/interrupt signal; leave pin5 unconnected on a simple input accessory rather than repurposing SAFE_N or loading it without a reviewed contract.

Recommend a separate ordinary-THT protected two-input accessory around MCP23008 PDIP18, GP0 and GP1. This preserves full sequential cam and all pressure channels and requires no new MCU GPIO. The latest official data sheet says GP7 is output-only, so do not select it as an input. The part supports3.3V/100kHz operation within its stated voltage/temperature range; the3.3V operating envelope must not be generalized from a125C product-page headline. External conditioning/bias, current budget, supply/reset/decoupling, unpowered pin injection, contact short-to-battery/reverse faults, cable shielding/entry and keyed connector contract all remain to be designed and reviewed. Internal weak pullups alone are not a protected dry-contact interface.

Keep the I2C harness short and internal; the external switch wires terminate at the accessory's protected connectors. Power the accessory from the carrier domain and review power-sequencing/injection instead of assuming an independently powered module is safe. Use a bounded low-priority acquisition task with transaction timeout; no I2C transaction in a timing ISR or synchronous high-priority engine calculation. Validate/read back IODIR/IPOL/IOCON/GPPU configuration before publishing qualified data and periodically detect reset/default-register drift. NACK, bus stuck, device reset, worker death, queue overflow and configuration mismatch invalidate both input channels. Bus recovery must not restart unrelated services or temporarily publish fabricated states.

A two-wire dry contact inherently cannot distinguish released from broken wire; health is acquisition/configuration health, not proof of harness continuity. A diagnosed switch circuit would need an additional end-of-line/multilevel design. No current Gerber/BOM/case or circuit tests implement this accessory. Exact parts, driver, CAD, fit and physical tests remain required before a full input-based secondary-table feature can be claimed.

References: [Microchip MCP23008 product](https://www.microchip.com/en-us/product/MCP23008), [Microchip DS20001919I](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP23008-and-MCP23008-Data-Sheet-DS20001919.pdf). The product being recommended for automotive designs does not qualify this proposed accessory or carrier.

## Required integration and comparison gates

1. Core/native: full source/mode combinations; below/equal/above condition limits; inactive-source policy; invalid/NaN/infinite/stale/future input; both polarities/channels; shared-input coherence; debounce boundaries/chatter/startup/reset; additive/multiplicative zero/saturation/negative spark; cranking bypass; soft-retard and per-cylinder ordering; EGO/DFCO/AE/deadtime/capacity interactions; default exact regression.
2. Configuration/persistence: new strict schema and migrations, wrong shapes/duplicates/unknown fields/nonnumeric values, no partial mutation on errors/allocation failures, whole-tune origin/CAS/storage failure, retained old document bytes, actual own MSQ roundtrip. Existing24KiB JSON maximum and5376-byte tune page need explicit sizing for two extra1152-byte maps and mode settings; preserve own008 and prior offsets. Never resize without checking target allocations/stack/heap.
3. UI/TunerStudio: both secondary map editors, unit-aware mode controls, basis acknowledgement, independent primary/secondary status, source-age faults, save/reload/import/export/stale-editor conflicts and actual offline application roundtrip. Online application support remains unresolved and must not be inferred from file editing.
4. Logs/radio: bounded RuntimeSample budget currently<=408B; full logs/runtime JSON and MSL fields with availability/source/reasons, generated browser/native parity; new versioned tuning runtime block if enlarged. Current250-byte schema3 has only two reserved bytes90..91, enough for a carefully versioned compact active/mode/source summary, not full debug values. Preserve schemas1..3/HMAC/replay/session contracts and explicitly gate nonrepresentable secondary modes or negotiate a new schema. Do not silently label a secondary result as primary-table-only telemetry.
5. Reference adapter: add before-start secondary profile and map writers/readback, validate all input before native mutation, preserve actual production coordinate scaling/interpolation/integer rounding. Add controllable independent virtual input pins and explicit synthetic ethanol stimulus if tested; do not replace production secondary functions. Preserve old executables/manifests/replays.
6. Coupled plant: neutral default exact regressions; equivalent multiply/add/switch calibrations and nonneutral perturbations; separate RPM/MAP/TPS switch crossings, equal boundaries, input toggles/bounce/stale failures, fuel-only/spark-only/both, sequential/semi/batch strategies, independent table sources, zero fuel and capacity limits. Compare portable/project target dispatcher and production reference32/16 models with at least selected half-step runs. Audit actual edges and delivered fuel/shaft/energy ledgers, including closed-pulse bounds during switching; do not accept proposal similarity alone.
7. Hardware: native ERC/DRC/parity and conditional circuit faults can support a reviewed draft, not establish physical timing, thermal, immunity, splash or fit. Physical I2C/accessory/switch and actuator HIL remains an explicit release hold.

Conclusion: implementing a core-only foundation now is aligned progress only if the ledger and documentation keep UI/tuning/target acquisition/hardware/plant acceptance explicitly pending. There is no present basis to mark the secondary-table feature complete, and no basis to claim full Speeduino equivalence.
