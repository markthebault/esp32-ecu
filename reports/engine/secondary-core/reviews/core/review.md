# Independent secondary-table core review

The final reviewed candidate is based on `e2b7c832b92384caae6cf379092ac6944129e237`. The production reference remains Speeduino `9ff5aae44de51fdc00d3fb1c7c2bfc1f0d0b3e20`. This assessment covers the shared control foundation and historical transport containment. It does not approve the pending complete secondary-table feature or the ECU for an engine.

## Findings and closure

1. **Qualification across configuration changes.** The initial core retained a qualified physical level across an input polarity change, and its BadTune early return did not reset secondary state. The current implementation fingerprints every Rule member and resets that consumer's filter whenever the rule changes. Engine BadTune also resets the secondary controller. Independent closure checks verify renewed qualification after polarity, channel, debounce, source/basis, condition, threshold and mode changes, plus an invalid-tune interval. Production configure paths already reset the complete controller; this strengthens direct core reuse too.
2. **Unrepresented historical transport data.** A core-enabled Tune must not be silently exported as own008, because a later historical decode necessarily resets secondary tables. The new generated `representable()` rejects both enabled configurations and Off-but-edited metadata/maps. Independent tests reject nine otherwise valid backend states without committing or changing backend bytes; a canonical backend then reopens successfully. The guard uses two small Rules and static immutable axes, not a full Tune stack temporary. Existing canonical JSON and all108 tested own008 pages remain unchanged. Full versioned configuration/UI/tuning integration remains pending.
3. **Tune growth and temporary ownership.** Two1152-byte maps made the previous resident scratch Tune exceed the session's existing size budget. The checked heap temporary keeps the native host Session at5,456 bytes, with a7,204-byte Tune allocated only while opening/burning. Independent malloc/free wrappers observe at most one scratch Tune, its existence throughout backend load/commit and no retained scratch after any tested success/error return. A failed burn returns0x85 for NoMemory/Busy and preserves page bytes, origin/base revision, dirty state and active data; a retry commits once. Stale revision and maximum revision reject before allocating. These host sizes and tracked allocation counts are not a measurement of target total heap peak, fragmentation, task stacks or service concurrency.
4. **Defensive scalar boundaries.** The current scalar helpers reject non-F32-representable diagnostic inputs while preserving F64 calculation results for valid table data. The filter rejects an invalid Rule before converting its debounce duration. Independent NaN/infinity/nonrepresentability and invalid-debounce checks pass.

The explicit `open()`/reconnect contract still abandons staged edits before loading a new snapshot, including if the new allocation fails. This is distinct from a failed **burn**, which retains staging. A blanket statement that every NoMemory path preserves staging would therefore be inaccurate. Backend loads must also honor their documented contract to supply a valid retained/default Tune with a StorageBlocked snapshot.

## Reviewed control policy and differences

- Fuel modes independently support Off, multiply, add, strict conditional switch and input switch. Source and stored axis units agree before operation; inactive stored map data are still validated. Project composition uses F64 interpolation/arithmetic and0..255 saturation, while Speeduino's cells/calculations retain integer quantization and rounding. This review does not assert numerical identity for fractional inputs.
- Physical TPS percent is used for condition thresholds. This is intentionally translated from Speeduino's half-percent status threshold and is distinct from its percent-times-four table coordinate. Equality keeps the primary table selected.
- Multiply/add acts on corrected primary spark. Switched spark applies the existing soft retard to the secondary absolute value. The tested core preserves the current carrier's-5..40deg running bounds; it does not adopt the reference's entire signed8-bit range. In sequential mode the per-cylinder offset is applied to the relevant raw map value before the existing nominal clamp/correction/composition chain. This order is explicit and tested, rather than assuming offsets are applied after composition.
- A static union qualifies all enabled secondary coordinate/condition dependencies, even while a conditional table is inactive. MAP conditions require MAP independently of coordinate source, pressure ratios require a valid EMAP role, and the existing J16 baro/EMAP conflict remains rejected. Missing inputs fault the consumer instead of becoming a false switch condition. Spark selection is bypassed while cranking, but the documented static pressure/ethanol dependency union remains required by the engine core.
- Input data carry a source, observed timestamp and validity. Current policy permits at most20ms read age/observation gap and defaults to20ms observed stable time. Repeated calls with one held timestamp do not advance qualification. A normal transition retains the prior qualified level while its candidate debounces. Unknown, invalid, future, reversed or stale samples invalidate immediately; recovery requalifies. Zero debounce is explicitly supported for comparison fixtures. This is a stronger declared project policy than Speeduino's direct digital read, not a matching acquisition implementation.
- Combined VE feeds the existing modeled fuel path before enrichment, trims, deadtime and capacity checks. Zero combined ordinary fuel suppresses deadtime-only openings; no actuator/scheduler policy was widened. The legacy observation comparison includes all three strategies, the existing AFR/transient modes, faults, clamps and four cylinder outputs.

The production architecture assessment independently runs the unchanged non-UNIT_TEST secondary functions and correction chain in342 controlled checks. This core review inspects the same pinned source and verifies the project's declared order and boundaries. It does not repeat that production-function probe or substitute its own formulas for a production engine-loop/plant comparison. Primary reference: [secondaryTables.cpp](https://github.com/speeduino/speeduino/blob/9ff5aae44de51fdc00d3fb1c7c2bfc1f0d0b3e20/speeduino/secondaryTables.cpp).

## Remaining acceptance boundaries

The new fields are deliberately unavailable to current JSON/own008 operators and both historical decoders reset them Off. No current host/native input JSON or target producer supplies table-switch/ethanol observations. The target protected switch accessory, bounded polling/health producer, new strict schema and binary layout, browser and TunerStudio editors, coherent JSON/runtime/log/radio diagnostics and migrations remain incomplete. Static dependency failures must remain visible even during a bypass; unavailable ethanol must never be zero-filled. Future target integration must maintain source-domain integrity and expose raw/debounced state, acquisition age, selected table, units, composition/clamp state and failure reasons.

No secondary-enabled coupled independent-plant run, production Speeduino loop comparison, target jitter/heap/stack measurement, physical I2C/switch test or actuator HIL was performed by this review. Existing selection/fuel core tests do not establish pulse delivery during a table switch. Shared-input sampling coherence, actual NACK/reset/worker-death handling and final backend/storage behavior need their integration gates. The current physical engine-output inhibition remains essential and unchanged. Source/native/simulator/CAD checks cannot establish real engine operation, electrical immunity, thermal behavior, splash resistance or printed fit.
