# Independent idle-air control architecture and reference review

Reviewed ECU HEAD `cbfbe4a` and unchanged Speeduino `9ff5aae44de51fdc00d3fb1c7c2bfc1f0d0b3e20`. This is an architecture/reference review before the proposed implementation, not approval of a completed idle controller. Production files and the external checkout were not edited. Isolated probes and this report are under this cache directory.

## Concrete findings

1. **High, comparison validity: native PWM time conversion disagrees with the timer.** `speeduino/board_native.cpp:172` returns 2 us from `getPwmTimerResolution()`. The project's reference HAL advances every 4 us (`scripts/build_speeduino_sim.py:54`; `tools/speeduino_sim_hal.cpp`). Consequently a configured 50 Hz idle valve produces 40 ms actual periods, or 25 Hz. Confirmed by the isolated probe in both native32/native16. Before comparing physical valve behavior, align the native conversion with the explicit HAL profile, record that adaptation, and assert measured period. Do not change upstream idleControl/idleInterrupt to disguise this mismatch.

2. **High, comparison validity: the native idle timer has no initial compare event.** Upstream `lib/ArduinoFake/SoftwareTimer.h` initializes compare to the counter type's maximum; the adapter's `enableTimer()` only enables callbacks. `initialiseIdle()` and `idleControl()` never seed `IDLE_COMPARE`. Native32 therefore produces no edges during the short run even with `idleLoad=50`; native16 begins only when its free-running counter first hits 65535. This is a reference-HAL initialization artifact, not evidence that the production idle strategy lacks authority.

   Use an explicit seeded native profile: immediately after idle initialization, snapshot virtual time, counter, old compare, width, tick size and pin level; set compare to `(counter + 1) mod 2^width`, so the first ISR occurs on the next tick. Give that first phase zero execution cost and label the assumption. Preserve an unseeded negative control that demonstrates the above missing-PWM behavior. Assert startup edge timing and the actual sustained duty before enabling comparative plant runs. Seed only at initialization, never on each control call or enable, which would truncate active pulses and conceal stop/restart behavior.

   This is a defensible **native** profile, not AVR emulation. AVR `board_avr2560.cpp:154` resets Timer1 to zero, starts its auxiliary counter at 16 us/tick and clears flags. Idle uses OCR1C/TCNT1 (`board_avr2560.h:161`), while fuel/ignition timers use 4 us. Current native16 changes counter width but does not model these separate resolutions, register flags, AVR integer widths, CPU cost or ISR priority. A true Mega timing profile needs the separate 16 us auxiliary clock and explicit reset OCR/flag semantics. Do not describe the seed as proof of the actual AVR power-on phase.

3. **High, upstream reference defect: disableIdle omits PWM_OLCL.** `speeduino/src/controllers/idle/idle.cpp:659` disables only PWM_CL and PWM_OL. PWM_OLCL falls through, sets `currentStatus.idleLoad=0`/idleOn=false, and leaves the prior pin/timer activity running. The seeded isolated probe confirms PWM continues after public `disableIdle()` in both timer widths, while OL and CL stop. Existing upstream disable tests cover only PWM_OL (`test/test_idle/test_disableidle.cpp`), so they miss this. Keep this behavior visible as a reference discrepancy; do not copy it or feed `idleLoad=0` directly to a simulated valve to hide it. Capture actual pin state, duty, current and opening across stop, zero demand and reinitialization.

4. **High, migration hazard: historical fields are generated from mutable current defaults.** `tools/engine_protocol_legacy.py:18` constructs NUMBERS, FLAGS and CURVES from current defaults. These drive historical wire offsets and `tools/engine_msq.py` expected constants for own001..004. Adding new idle fields to existing settings/curves without freezing those lists alters old layouts, revision offset268 and historical MSQ accepted sets. Freeze the exact schema3 field lists/defaults. Keep the new schema4 idle object and own005 layout explicit. Legacy JSON/MSQ imports must disable the old virtual idle flag, supply fixed reviewed defaults, and not inherit enabled idle parameters from the editor's current base. Preserve original stored bytes until an explicit successful save, including old revision/CAS behavior.

5. **Medium, plant causality: the main comparison currently ignores idle.** `ResearchPlant.integrate(..., idle_pct=0)` already forwards the value into AirPath, but both calls in `tools/compare_engine_controllers.py:133,141` omit it. The Modelica adapter already has the idle area term. Route the separately modeled executed valve opening to every integration segment, including timer, tooth, cam and control boundaries. Do not directly connect the latest proposed duty or RPM error to manifold area. The unmodified local SIL already has a direct idle percentage coupling; it is not an independent electrical actuator check.

6. **Medium, telemetry boundaries:** own004 live216 plus more than40 bytes crosses the current256-byte `r` command count limit in `firmware/include/ecu/tuning_session.hpp`. RuntimeSample engine channel masks are uint8 and cannot represent idle channel8. The authenticated ESP-NOW engine frame is already232 bytes, close to its250-byte v1 bound. Use explicit idle fields/validity and a versioned or separate capability for radio extension; test real TunerStudio read boundaries. Keep requested duty, shadow executed pin state, estimated RL current/opening, and physical observation distinct.

## Recommended controller contract

The proposed on/off, PWM open-loop and PWM closed-loop with feedforward scope is coherent for a first real IAC increment. Keep the default disabled and physical output policy inhibited. A normally closed, single PWM solenoid is a precise actuator contract; it does not cover stepper, H-bridge/two-coil or DBW control.

- A single master enable plus mode selects the algorithm. A disabled mode and master false must give one clear effective state. Since legacy target/KP/KI remain editable master fields, make any temperature target curve an explicit additive RPM offset from the base target, or make the duplicate field read-only. Two editable absolute targets are ambiguous.
- Evaluate safety and input validity before control math. On stale/reversed control time, bad tune/input, required sync/phase loss, executor fault, overheating, stopped engine, or disabled policy, command the NC actuator off immediately and reset eligibility/integrator/taper history as specified. Do not let a later auxiliary computation override an earlier return/cut. Rev-cut and cylinder-capacity behavior should be intentional and covered explicitly, not inherited from return placement.
- Cranking uses the temperature crank duty with no PI. Start the crank-to-run taper on a genuine cranking-to-running transition. Repeated running updates and temporary throttle excursions must not restart a full crank taper. A stopped/restart sequence resets it. Zero-duration taper must be valid without division by zero.
- Running open-loop uses the temperature feedforward table. Closed-loop adds PI only after TPS and RPM eligibility has remained true for the entry delay. Use separate entry/exit TPS and RPM hysteresis; clear the pending entry timer on every predicate break. TPS high and DFCO must explicitly exit PI and select the documented off/open-loop/taper state. Prevent integral windup when returning from throttle/DFCO.
- Define the PI units in duty percentage points per RPM and percentage points per RPM-second. Use monotonic elapsed time at the controller's specified period. Do not integrate the full engine task interval repeatedly when the PI holds its last output, or integrate once for every replayed overdue slot. A missed/stale deadline exits control instead of integrating a very large interval.
- Bumpless entry preloads I from the previous allowed actuator command minus new FF and P. Apply limits deliberately: if the previous command exceeds a new hard bound, the safe clamp takes precedence over exact continuity. Conditional integration or equivalent back-calculation must reject error pushing further into saturation and allow recovery toward the legal range. Reset/rebase on enable/mode/tune changes rather than carrying an old I into a different valve or limit range.
- Validate finite monotonic temperature axes; finite targets; 0..100% duty; coherent min/max, entry/exit thresholds and delays; positive PWM/control periods; bounded gains; and physically supported frequency/polarity. Define whether crank duty can exceed running bounds and how on/off thresholds hysterese. Reject invalid disabled configurations too, so switching modes cannot activate an unvalidated latent tune.
- Diagnostics should include effective target, feedforward, P, I, requested and limited duty, saturation direction, control state, eligibility/gate reason and age, plus separate executor/valve observations. No unavailable physical measurement should appear as a valid zero. The UI, API, INI/MSQ and log fields must use the same units and enum definitions.

## Exact pinned Speeduino configuration/call/output path

Use the actual production setup/loop and unchanged idle controller, not copied PID equations as the comparison implementation. Configure an explicit reference profile before persisted production setup (and verify it afterwards):

- `configPage6.iacAlgorithm`: PWM_OL2, PWM_CL3, PWM_OLCL6; ONOFF1 for its own comparison. `iacChannels=0`, `iacPWMdir` explicit, `iacPWMrun=false` unless key-on opening is intentionally compared; idle-up/AC adders disabled for baseline.
- `idleFreq` is stored in 2 Hz units; use `FREQUENCY.toRaw(hz)`, report the actual representable even frequency. `iacCrankBins[4]`, `iacBins[10]` and idle target temperature axes use Celsius+40; fill duty tables in integer percent. `currentStatus.coolant` itself is signed user Celsius. `CLIdleTarget` is RPM/10; TPS and `iacTPSlimit` are in0.5% raw units.
- `iacCLminValue/maxValue` are percent for PWM. `idleTaperTime` is0.1s ticks and is used by PWM_OL; the pinned PWM_OLCL path has no crank-to-run taper even though its stepper equivalent does. Do not silently implement a taper in the reference adapter.
- `initialiseIdle(true)` constructs pin polarity, timer max count and PID limits. Production `speeduino.ino:353` calls PWM idleControl at10Hz; sensor TPS runs30Hz; CLT/IAT/battery run4Hz (`sensors.h`), and CLIdleTarget is calculated at4Hz (`speeduino.ino:308`). Preserve sensor ADC quantization/filtering rather than assigning all currentStatus fields in full-plant comparisons.
- PID retune has a250ms minimum interval (`idle.cpp:45`). With a100ms caller and1Hz retune resetting its clock, updates normally occur at300/300/300/100ms intervals. `setSetPoint()` is inside the1Hz retune helper, so the effective PID setpoint updates at1Hz even when CLIdleTarget changes at4Hz. Log actual compute/output update times instead of asserting a uniform4Hz controller.
- OLCL resets I when raw TPS exceeds its threshold or RPM exceeds target+hysteresis (`idle.cpp:481`); unlike stepper OLCL, it does not apply the stored previous DFCO flag to the PWM output. Record these production differences rather than simulating the project's gating inside the reference.
- Capture idle1 pin transitions as a distinct ninth actuator. Translate inverted physical level to energized coil state only using the configured polarity. Capture the0% and100% constant states without requiring edges. Report measured frequency, electrical high time, maximum contiguous high time, last update age, and stop/fault state. Do not use idleLoad as actual duty.

### PID scaling

Let `M = floor(1e6/(PWM_tick_us*frequency_hz))`, and let `e = targetRPM - RPM`. Production PWM PID output is in quarter timer counts, not duty percent. Internal output limits/feedforward are then scaled by1024. With a250ms sample:

```
Kp_scaled = 32 * Kp_raw
Ki_scaled =  8 * Ki_raw
Kd_scaled = 32 * Kd_raw
u_quarter = FF_quarter + (32*Kp_raw*e + 8*Ki_raw*sum(e)
                         + 32*Kd_raw*(previousRPM-RPM))/1024
PWM_count = u_quarter >> 2
duty_percent = 100*PWM_count/M
```

Clamp/conditional integration occurs in PidCore; rounding and shifts matter. Nominal normalized P gain is `100*Kp_raw/(128*M)` percentage points/RPM; nominal I gain over four updates per second is `100*Ki_raw/(128*M)` percentage points/(RPM*s). At50Hz and a corrected4us native PWM tick, M5000 gives raw Kp192 for0.03%/RPM and raw Ki128 for0.02%/(RPM*s). These are mappings, not evidence of a good tune. The INI labels alone are not normalized physical gains. Jitter and integer rounding still differ from the project's PI.

Native16 does not change host C++ int/long widths, so AVR16-bit promotion/overflow behavior is not established by either native profile. Use bounded declared gains/input errors and do not claim AVR numerical equivalence. Any future target comparison must check output limit shifts and intermediate PID multiplication under actual target integer widths.

## Independent actuator/plant assessment

The existing Modelica area term is `0.72*(17e-6 + 6e-4*TPS/100 + 2e-5*idle_opening/100)`. Keep that geometry, combustion, rotor, injector deadtime and friction fixed for both ECUs. Use one independently parameterized RL coil/current-to-force/NC mechanical opening model for both, driven by actual PWM pin transitions. Use physical circuit polarity and a documented flyback current-decay assumption. Do not retune the valve geometry/friction to make either controller pass a preferred outcome. Controller calibration may be compared separately from identical-tune results.

The isolated existing-FMU check in `airpath-probe.json` holds the shaft fixed and commands opening0/25/50/100% at600/900/1200RPM. At900RPM, zero throttle, after1s, opening0→100 increases MAP24.83→46.64kPa and cylinder air3.05→6.32g/s. The maximum mass residual across12cases is below6e-16kg and energy residual below1.2e-6J. This establishes a monotone causal air path in these cases, not idle stability, actuator realism, a calibrated valve, or physical engine validation.

Required negative controls: valve disconnected/stuck closed, mechanically stuck open, wrong polarity, PWM frequency changed while duty held fixed, long output hold/producer timeout, sensor or trigger loss, and PI disabled/frozen integral under the same load step. A disconnected/stuck valve should break recovery without breaking mass/energy accounting. Assert current/opening/airflow change before attributing RPM recovery to control. Include step-size halving for PWM/RL coupling and sharp duty0/100 transitions. Keep any artificial force/dyno/starter work in ledgers.

## Acceptance gates before declaring this increment complete

1. Native controller tests cover default-off, all modes, crank/run/restart, cold/warm curve endpoints/interpolation, zero taper, bumpless entry, repeated eligibility interruptions, boundary TPS/RPM hysteresis, saturation in both directions and recovery, disabled/tune-change/reset, DFCO, faults, stale/reversed time, first time zero and long gaps. Assert internal state and actual permitted duty, not only RPM trajectories.
2. Reference tests cover seeded/unseeded startup, configured vs measured frequency, 0/1/50/99/100%duty, polarity, both native widths and wrap, open-loop taper timing, actual update cadence, full stop and mode switches. Explicitly retain evidence of the unmodified OLCL disable discrepancy.
3. Migration tests retain bytes/revision for schema1/2/3 storage load; migrate old idle_enabled true/false safely; import each exact own001..004 example from both JSON/MSQ with fixed defaults; reject unknown/duplicate/missing/cross-version fields; and roundtrip all own005 idle fields through browser, native target, whole-page protocol and actual TunerStudio. Confirm a legacy import cannot retain the active editor's enabled new idle path.
4. Protocol tests cover reserved bytes, chunk boundaries across each extension, whole-tune CAS and persistence/restart, validation failure without partial mutation, source freshness/validity, and logs unavailable data. If live data exceeds256bytes, verify the application's real read behavior rather than only codec unit tests.
5. Both real controller cores run the identical fixed independent plant and valve parameters through crank/start, warm/cold targets, target changes, load steps within/beyond actuator authority, throttle blip and DFCO return, stall/restart, trigger/sensor loss and valve failures. Compare commanded/actual current/opening, air flow, target error, overshoot, recovery/stall and ledger residuals. Separate plant limitations, harness defects, unmodified upstream defects and actual project control defects.

The current findings do not prevent implementing the proposed feature. They prevent treating an unseeded, incorrectly clocked or status-only Speeduino run as a valid control comparison. Physical GPIO, electrical/thermal valve-driver behavior and engine operation remain unqualified.
