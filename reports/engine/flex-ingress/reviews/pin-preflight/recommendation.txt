Prefer GPIO38 for protected flex capture and a new on-carrier MCP23008 at 0x21 for the advisory RGB LED. Keep GPIO45/46 unallocated. This is a recommendation for a separately identified development hardware revision, not a fabrication or physical qualification approval. The frozen findings, URLs, source hashes and detailed startup/disable contracts are in preflight-review.json.

The two-strap proposal is feasible as a constrained fallback, but its stated all-reset guarantee is not established. Chip straps are sampled at Chip Reset; a GPIO45 runtime high does not continuously select flash voltage. CPU reset, Core reset, System reset, GPIO hold, EN/reset and partial power cannot be treated as the same HiZ event. The pinned restart path retains GPIO while resetting CPUs/MCPWM, and held outputs can remain driven. A pull-down cannot override an active high driver. A retained GPIO45 high across CPU/Core restart does not itself reselect flash voltage, because those resets do not re-sample Chip Reset straps; it remains a gate/producer restart issue. The normal cold/EN-reset pull-down default is supported. GPIO46 must be low for joint download with GPIO0 low, through the strap hold interval. Genuine PSRAM WROOM modules have factory VDD_SPI eFuse configuration; the selected supplier board has not been physically identified/read back, so that exception cannot be assumed.

The new allocation exchanges those boot/flash dependencies for a noncritical peripheral workload that can be bounded and observed. GPIO38 currently drives the separate WS2812 in compact builds; generic non-compact builds also use GPIO38 for ARM. New and historical ownership must be mutually exclusive at build time. MCPWM setup does not turn off an existing output driver. Explicitly disable output before capture input setup and exclude every later RMT initialization/write. Old WS2812 builds remain for old wiring; they are not electrically compatible with the new input wiring.

The current A4 U7 has two spare SN74HC14N gates at 3.3 V. A new revision can potentially cascade them as a non-inverting Schmitt conditioner; the additional MCP23008 would then be the only added DIP. This does not approve copied input RC values, surge protection, off-state back-power behavior or pulse-width accuracy. Review sensor LOW-pulse polarity and characterize conditioner skew at the 1/3/5 ms endpoints. HC08 at 3.3 V is a possible AND-gate fallback; existing 5 V HCT08 gates cannot be directly used as a 3.3 V GPIO buffer. A disabled open-drain/tri-state output is not inherently low. For example, 4.7k pull-up plus 10k pull-down yields only 2.245 V, below the 2.475 V input-high minimum at 3.3 V.

For either capture pin, reserve the third channel of the existing group0 APB timer at priority 3, prescale 1, both edges. Keep the common timer running and calibrated; do not reset it for flex reconfiguration. Capture hardware has a single latched event per channel. Use a bounded integer ISR/queue, epoch/revision fences, and fast flex-only suppression of overflow or noise storms. Startup and restart must exclude pre-epoch/pending/partial cycles, preserve crank/cam status, and require a new complete window. Target provenance and a fault ACK belong to a coherent completed control observation, never to configuration or queue clearing.

For the LED, one I2C owner must coordinate 0x20 and 0x21. Switch acquisition has priority and both consumers share one total 3 ms budget per 5 ms tick. Ideal wire clocks suggest 1.62 ms for the existing guarded switch read and 0.63 ms for an LED write/readback pair; software, stretching and timeout quantization add cost. This is feasibility arithmetic, not target WCET. Skip/coalesce LED updates without slack, bound retries, and retain bus ownership while either client needs it. Allocation/deletion do not have a proven hard deadline. Initialize off OLAT before output direction and verify configuration/latch state. Select actual LED/resistors for guaranteed voltage headroom and conservative current.

Expose desired LED command separately from last verified latch, age and bus fault/unknown status. A failed bus or CPU can leave green latched. The failed bus cannot guarantee red/off, and register readback cannot prove light output. Keep color advisory; a true live-health indication needs an independent timeout or an explicitly recognized blink convention. LED absence alone must not introduce a fuel/spark dependency, while any shared-bus impact on required switches retains the existing fail-closed input behavior.
