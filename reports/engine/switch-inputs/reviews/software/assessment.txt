Current software assessment

The intended single-monitor-task ownership, fixed address, pre-write marker guard, readback of all semantically owned registers, alternating physical GP6 feedback, independent trailing IODIR check, source-read-start timestamp, measured whole-operation budget, floored remaining per-call timeout, and fault-ID consumption latch form a coherent acquisition design. The marker and feedback do not authenticate device identity. Saving an Input rule is the explicit ownership choice. Off does not produce healthy/open inputs or refresh source timestamps. The current app preserves the previous request mask if its zero-wait engine mutex read skips, passes copied samples through web::Sample to bind_inputs(), and acknowledges a source fault only after observe() completes for that snapshot.

The source latch is important: successful wire reads do not make the source valid while an invalid sample awaits a completed controller observation. A later fault obtains another identity, so an old acknowledgment cannot clear it. Acknowledgment itself does not publish a fresh sample. The core then applies its normal source-time qualification and20ms freshness rules. Sensor/phase/configuration gates and selected physical-output inhibition remain separate existing layers.

The current SDK adapter retains partially allocated resources on add/remove/delete failures rather than overwriting handles. It performs no register traffic in Off mode and retries cleanup at100ms cadence. SDK allocation/deletion APIs and internal locks have no caller-supplied hard deadline. Per-transfer timeouts plus elapsed rejection must therefore be described as a measured data-acceptance budget, not proof of a3ms task execution deadline. Exact SDK source references are retained with the final packet.
